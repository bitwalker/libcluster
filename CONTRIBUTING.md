# Contributing

## Supported test environments

The package retains its Elixir 1.13 requirement. CI tests these explicit pairs on Ubuntu 24.04:

| Elixir | Erlang/OTP | Rebar3 |
| --- | --- | --- |
| 1.13.4 | 24.3.4.17 | 3.21.0 |
| 1.17.3 | 27.3.4.19 | 3.28.0 |
| 1.20.5 | 29.1.2 | 3.28.0 |

OTP versions older than 24.3 are no longer covered by CI. New combinations should follow the
[Elixir compatibility table](https://hexdocs.pm/elixir/compatibility-and-deprecations.html)
and [setup-beam's runner support](https://github.com/erlef/setup-beam#supported-software).
Use `mise` to install local Erlang and Elixir versions. For example:

```sh
mise install erlang@29.1.2 elixir@1.20.5
mise exec erlang@29.1.2 elixir@1.20.5 -- mix local.hex 2.6.0 --force
mise exec erlang@29.1.2 elixir@1.20.5 -- mix deps.get
mise exec erlang@29.1.2 elixir@1.20.5 -- mix test
```

Keep Hex archives and build directories separate when switching OTP versions. Use the matrix's
Rebar version, and set `MIX_REBAR3` to its executable when using a manually installed Rebar;
older Mix versions do not search `PATH` for it.
Use an absolute path for `MIX_BUILD_PATH`, for example `"$PWD/_build/test-otp24"`, so older Mix
versions and dependencies resolve the same build directory.

Kubernetes tests use a loopback HTTPS server with ephemeral ports and certificates generated by
OTP's `public_key` test helpers. They need no Kubernetes cluster, recorded HTTP traffic, or test
mocking dependencies. The TLS tests exercise the same real HTTP client as production discovery.

Before submitting a change, run:

```sh
mix format --check-formatted
mix deps.unlock --check-unused
mix hex.audit
MIX_ENV=test mix compile --warnings-as-errors
mix test --warnings-as-errors
MIX_ENV=prod mix compile --warnings-as-errors
mix docs --warnings-as-errors
mix hex.build
```

Run formatting and documentation checks with the newest pair above. The test job compiles
dependencies before applying strict compilation to this project's code. Dependency warnings
must be reviewed rather than hidden with global compiler options. `mix hex.outdated` is useful
for dependency reviews; a newer version alone is not a failed compatibility check.

## Workflow maintenance

Install [actionlint 1.7.12](https://github.com/rhysd/actionlint/releases/tag/v1.7.12),
[zizmor 1.31.1](https://github.com/zizmorcore/zizmor/releases/tag/v1.31.1), and the pinned
GitHub CLI extension:

```sh
gh extension install github/gh-actions-lock --pin v0.4.0
```

After editing workflows or action versions:

```sh
gh actions-lock
gh actions-lock --verify
actionlint
zizmor --offline .github
```

Review the generated `.github/workflows/actions.lock` alongside the workflow change; never edit
it by hand. All workflows must remain onboarded. The frozen `--verify` check reads upstream
metadata and fails for incomplete or rejected pins; `--verify-local` is an optional offline
coverage check, not a substitute. Updating an already locked action intentionally may require
`gh actions-lock --relock`; inspect every changed commit, including transitive actions.

GitHub's native lockfile pins action commits at execution time, allowing readable exact tags in
workflows. That is why the repository disables only zizmor's `unpinned-uses` audit. Docker images
still need digest references, reusable workflow calls need full commit SHAs, and independently
downloaded tools need their own reviewed versions. The automation job pins actionlint's image,
zizmor's action/CLI, and the lockfile generator. No lint job needs secrets or write permissions.

Dependabot groups action updates weekly and checks Hex dependencies monthly, with a seven-day
cooldown for routine updates. Review lockfile changes with those PRs. Workflow checks run for
every PR, including documentation-only changes, so required checks are not left pending by
path filters. Configure required checks only after successful hosted runs.
